Animation

Animation do jagah ho sakta hai — CSS ke andar (transition/@keyframes), ya JS ke andar (requestAnimationFrame). Dono ka math same hai: ek timing function jo time-fraction (0→1) ko progress (0→1) mein map karti hai. Bezier curves us timing function ka mathematical foundation hain. Is chapter mein hum root-level dekhenge ki browser ke andar transform/opacity animations GPU pe kyun chalte hain, jabki width/left jaise properties har frame layout trigger karte hain — aur ek reusable JS animate() helper banayenge jo setInterval ke bina, sahi tareeke se kaam karta hai.

Bezier curves — CSS easing ka foundation

Bezier curve ek smooth mathematical curve hai jo control points se define hoti hai. Curve ka "order" points ki count minus 1 hota hai — 2 points = linear (straight line), 3 points = quadratic, 4 points = cubic. CSS animation timing ke liye cubic bezier use hota hai — 4 control points, jinme se pehla aur aakhri fixed hote hain.

Root formula (De Casteljau construction): har t (0 se 1 tak) ke liye, control points ke beech ke segments pe proportional points nikalo, unhe connect karo, phir wahi process recursively repeat karo jab tak ek hi point na bache — wahi point curve ka part hota hai. Cubic bezier ka closed-form formula:

Cubic bezier formula (math, reference ke liye)
// P = (1-t)^3 * P1 + 3(1-t)^2 * t * P2 + 3(1-t) * t^2 * P3 + t^3 * P4
// P1 = (0,0) start, P4 = (1,1) end — ye dono CSS mein FIXED hote hain
// P2 aur P3 hi hain jo hum control karte hain — cubic-bezier(x1,y1,x2,y2) mein
function cubicBezierY(t, y1, y2) {  // simplified: sirf y (progress) axis ka approx
  const mt = 1 - t;                          // mt = "1 minus t" — formula mein baar baar chahiye
  return 3 * mt * mt * t * y1   // P1.y=0 term drop ho gaya kyunki 0 hai
       + 3 * mt * t * t * y2
       + t * t * t;              // P4.y=1 term simplify ho gaya (t^3 * 1)
}

Curve hamesha apne control points ke convex hull ke andar rehta hai, aur control points ko move karne se curve intuitively predictable tareeke se change hota hai — ye property hi bezier curves ko designers/tools (Photoshop pen tool, SVG paths, CSS easing) mein useful banati hai.

cubic-bezier(x1, y1, x2, y2) — control points intuition

CSS ke transition-timing-function aur animation-timing-function cubic-bezier(x1, y1, x2, y2) accept karte hain. Yahan x-axis time (0→1, animation ka fraction) hai aur y-axis progress (0→1, property ki value kitni complete hui) hai. Fixed points: P1=(0,0) — start, P4=(1,1) — end. Tum sirf P2=(x1,y1) aur P3=(x2,y2) control karte ho.

Built-in keywords ke underlying cubic-bezier values
transition-timing-function: linear;                            /* == cubic-bezier(0, 0, 1, 1) — constant speed */
transition-timing-function: ease;                              /* == cubic-bezier(.25, .1, .25, 1) — default, slow-fast-slow */
transition-timing-function: ease-in;                           /* == cubic-bezier(.42, 0, 1, 1) — slow start, fast finish */
transition-timing-function: ease-out;                          /* == cubic-bezier(0, 0, .58, 1) — fast start, slow finish */
transition-timing-function: ease-in-out;                      /* == cubic-bezier(.42, 0, .58, 1) — slow-fast-slow, symmetric */
transition-timing-function: cubic-bezier(0.17, 0.67, 0.83, 0.67); /* custom "bouncy" feel — y values 0-1 ke bahar bhi ja sakte hain (overshoot) */

Intuition: y1 (P2 ka y) batata hai animation start mein kitna "fast progress" ho raha hai — high y1 matlab jaldi progress. x1 batata hai wo progress kis time pe target hai. Agar y1 ya y2 ko 1 se zyada ya 0 se kam set karo (jaise cubic-bezier(.68, -0.55, .27, 1.55)), to animation apne final value se overshoot kar sakti hai (bounce-back / elastic feel) — kyunki y-axis clamp nahi hai, sirf x-axis (time) 0-1 mein clamp rehta hai.

CSS transition — sabse simple animation

transition ek property change ko instant se smooth banata hai — jab bhi koi CSS property value change hoti hai (hover, class add/remove, JS se style set), browser us change ko transition duration ke over interpolate kar deta hai.

transition shorthand: property duration timing-function delay
.box {
  width: 100px;                                        /* initial state */
  transition-property: transform, opacity;       /* sirf ye 2 properties animate hongi, 'all' mat use karo perf ke liye */
  transition-duration: 0.3s;                             /* 300ms mein complete */
  transition-timing-function: ease-out;              /* speed curve — fast start slow end */
  transition-delay: 0s;                                /* start hone se pehle wait — yahan 0 */
}
.box:hover {
  transform: scale(1.1);                            /* target state — hover pe transition trigger hoga */
  opacity: 0.8;
}

/* Shorthand — sab ek line mein, multiple properties ko comma se separate karo */
.card {
  transition: transform .2s ease-out, box-shadow .2s linear .05s; /* transform 200ms ease-out, box-shadow 200ms linear 50ms delay ke baad */
}

transition-timing-function mein steps(n, start|end) bhi valid hai — continuous curve ki jagah n discrete jumps mein animate karta hai (sprite-sheet animations ke liye useful, jaise ek walking-character sprite ko frame-by-frame flip karna).

transitionend event

Transition complete hone pe transitionend fire hota hai — har animated property ke liye alag se, agar shorthand mein multiple properties animate ho rahi hon.

transitionend + JS-triggered transition
const box = document.querySelector('.box');          // element reference le liya

box.addEventListener('transitionend', (event) => { // listener attach kiya
  console.log(`${event.propertyName} khatam hua, ${event.elapsedTime}s mein`);
  // propertyName: kaunsi property finish hui (jaise 'transform', 'opacity')
  // elapsedTime: seconds mein duration, transition-delay EXCLUDE hoke
});

// JS se class add karke transition trigger karna — declarative aur reusable
box.classList.add('is-active');                          // CSS rule .is-active mein target state hoti hai

// Direct style set karke bhi trigger ho sakta hai — same effect
box.style.transform = 'translateX(200px)';            // browser current -> new value ko animate karega

@keyframes + animation-* properties

transition sirf "state A → state B" ek baar animate karta hai. Jab tumhe multi-step, repeating, ya independent (bina kisi trigger ke, page load pe hi shuru) animation chahiye, to @keyframes + animation-* use karo.

@keyframes definition + animation-* properties
@keyframes pulse {                        /* 'pulse' naam se ek reusable animation define ki */
  0%   { transform: scale(1);   opacity: 1; } /* start keyframe */
  50%  { transform: scale(1.15); opacity: .7; } /* midpoint — halfway state */
  100% { transform: scale(1);   opacity: 1; } /* end keyframe, from ka alias 0%/to ka alias 100% */
}

.notif-dot {
  animation-name: pulse;                    /* @keyframes pulse ko is element pe apply kiya */
  animation-duration: 1.5s;                /* ek cycle 1.5 second ka */
  animation-timing-function: ease-in-out;  /* speed curve — same bezier semantics */
  animation-delay: 0s;                    /* start hone se pehle wait */
  animation-iteration-count: infinite;      /* hamesha chalte raho — number bhi de sakte ho e.g. 3 */
  animation-direction: alternate;            /* har iteration ke baad reverse — 0%→100%→0%→100%... */
  animation-fill-mode: both;                  /* animation se pehle/baad bhi keyframe wali value hold rahe */
  animation-play-state: running;              /* JS se 'paused' set kar ke pause/resume control kar sakte ho */
}

/* Shorthand — order: name duration timing-function delay iteration-count direction fill-mode */
.notif-dot {
  animation: pulse 1.5s ease-in-out 0s infinite alternate both;
}

animationend event

animationend — pause/resume via JS
const dot = document.querySelector('.notif-dot');        // element pakda

dot.addEventListener('animationend', (e) => {    // sirf non-infinite animations pe fire hoga
  console.log(e.animationName, e.elapsedTime);  // kaunsa @keyframes naam, kitna time laga
});

// pause/resume — animation-play-state ko JS se toggle karna
dot.addEventListener('click', () => {
  const running = getComputedStyle(dot).animationPlayState === 'running'; // current state check
  dot.style.animationPlayState = running ? 'paused' : 'running'; // toggle
});

Root cause: compositor thread vs layout thrash

Browser render pipeline 3 broad stages mein chalta hai: Layout (geometry — element kahan hai, kitna bada hai), Paint (pixels — colors, shadows, text), aur Composite (final layers ko screen pe assemble karna, GPU ka kaam). Jab tum width, left, top, margin jaisi properties animate karte ho, browser ko har single frame pe Layout se dobara chalna padta hai (kyunki geometry badli), phir Paint, phir Composite — teeno stages, 60 baar per second.

Lekin transform (translate/scale/rotate) aur opacity animate karne pe, browser Layout aur Paint dono skip kar sakta hai — element ka pehle se painted pixel-layer GPU pe already exist karta hai, aur transform/opacity sirf us layer ko move/blend karne ka instruction hai. Ye kaam compositor thread pe hota hai — jo main JS thread se independent hai — isliye main thread busy hone par bhi (heavy JS chal rahi ho) ye animation smooth chalti rehti hai.

🧠 Senior Dev Note: sirf transform/opacity 60fps ke liye reliable hain

Production mein agar tumhe consistently 60fps animation chahiye (khaaskar mobile pe), to sirf transform aur opacity animate karo — inhe "compositor-only properties" kehte hain. Position ke liye left/top ki jagah transform: translate(x, y) use karo, size ke liye width/height ki jagah transform: scale(). Agar kisi wajah se layout property animate karna hi padhe, to will-change: transform jaisi hints se browser ko pehle se element ka alag compositor layer banane ka signal de sakte ho — lekin overuse se memory bloat hota hai (har will-change layer GPU memory leta hai), so sirf actively-animating elements pe hi lagao, aur animation khatam hone pe hata do.

requestAnimationFrame — sahi tareeka

JS-driven animation (jo CSS se possible nahi — complex paths, physics, multiple interdependent properties) ke liye purana approach setInterval(fn, 16) tha (16ms ≈ 60fps). Ye galat approach hai, kai reasons se.

⚠️ setInterval animation ke liye kabhi mat use karo

(1) Timing precision: setInterval ka delay display refresh rate se sync nahi hota — browser ka repaint cycle apni jagah chalta hai, aur agar tumhara interval us cycle ke beech mein fire hua, to us frame ka kaam wasted hai (agla repaint tab tak wait karega). (2) Multiple animations = multiple independent timers, jinhe browser ek saath group nahi kar pata — result: zyada layout/paint cycles, zyada CPU. (3) Background tabs: tab hidden hone par bhi setInterval chalta rehta hai (throttle hota hai ~1s tak, but band nahi hota) — battery aur CPU waste. requestAnimationFrame in teeno problems ko root se fix karta hai: callback browser ke agle actual repaint se pehle exactly ek baar fire hota hai, saare rAF callbacks ek hi frame mein batch hote hain, aur tab hidden hone par rAF automatically pause ho jaata hai.

requestAnimationFrame — basic syntax
let requestId;                                    // id store karenge cancel karne ke liye

function step(timestamp) {                       // browser ye function call karta hai, arg = high-res timestamp (ms)
  console.log(timestamp);                        // performance.now() jaisa hi origin (page load se ms)
  requestId = requestAnimationFrame(step); // agle repaint ke liye khud ko dobara schedule karo — loop banaya
}

requestId = requestAnimationFrame(step);       // pehli baar schedule kiya, loop shuru

// rok-na ho to:
cancelAnimationFrame(requestId);              // pending callback cancel — clearInterval jaisa hi concept

Generic animate() helper function

Har baar manually rAF loop likhna repetitive hai. Ek reusable animate() helper banate hain jo teen cheezein leta hai — duration (kitni der), timing (progress curve function, wahi jo hum bezier se seekh chuke), aur draw (actual DOM ko update karne wala function, jise sirf progress value pata hona chahiye).

animate({duration, timing, draw}) helper
function animate({duration, timing, draw}) {   // destructured options object leta hai — readable call-site ke liye
  const start = performance.now();                // high-resolution start timestamp (sub-millisecond precision)

  function tick(time) {                          // rAF callback — time bhi high-res timestamp hai
    let timeFraction = (time - start) / duration; // abhi tak kitna fraction time beeta (0 se shuru, badhta hua)

    if (timeFraction > 1) timeFraction = 1; // clamp — last frame duration se thoda over-shoot ho sakta hai, cap laga do

    const progress = timing(timeFraction);       // time-fraction ko easing curve se guzaar ke "visual progress" banaya

    draw(progress);                             // caller ka draw function — DOM update yahin hota hai

    if (timeFraction < 1) {              // abhi khatam nahi hua
      requestAnimationFrame(tick);          // agle frame ke liye khud ko phir schedule karo
    }
  }

  requestAnimationFrame(tick);                     // loop kickstart karo
}

Ab timing functions — inhi ka bezier-jaisa role hai, bas hum inhe raw JS math se likh rahe hain instead of CSS cubic-bezier() string:

Timing functions + ease-out wrapper
function linear(timeFraction) {
  return timeFraction;                     // progress == time, constant speed — CSS ke linear jaisa
}

function quad(timeFraction) {
  return Math.pow(timeFraction, 2);       // t^2 — start mein slow, end mein fast (ease-in jaisa feel)
}

function circ(timeFraction) {
  return 1 - Math.sin(Math.acos(timeFraction)); // circle-arc based curve — dramatic slow start
}

function makeEaseOut(timing) {              // koi bhi "ease-in-style" function le ke "ease-out" bana deta hai
  return function(timeFraction) {
    return 1 - timing(1 - timeFraction); // time ko reverse karo, result ko reverse karo — mirror trick
  };
}

const quadEaseOut = makeEaseOut(quad);          // ab fast-start slow-end wala quad ban gaya
Real usage: circle grow + moving ball with ease-out
// Example 1: ek circle ko smoothly grow karna width % ke through
const circle = document.querySelector('.circle');       // target element

animate({
  duration: 1000,                                 // 1 second
  timing(timeFraction) { return timeFraction; }, // linear — inline shorthand method syntax
  draw(progress) {
    // GPU-friendly: transform: scale() use kiya, width NAHI (layout thrash se bachne ke liye)
    circle.style.transform = `scale(${progress})`; // 0 se 1 tak scale badha
  }
});

// Example 2: ek ball ko horizontally move karna, ease-out feel ke saath
const ball = document.querySelector('.ball');          // target element
const distance = 500;                             // total pixels move karni hai

animate({
  duration: 2000,                                 // 2 seconds
  timing: quadEaseOut,                        // upar wala wrapped function reference
  draw(progress) {
    // left ki jagah translateX — compositor thread pe chalega, reflow nahi hoga
    ball.style.transform = `translateX(${progress * distance}px)`; // 0 se 500px tak
  }
});

Notice karo: draw function mein hamesha transform use kiya, kabhi width ya left nahi — ye wahi compositor-only-property principle hai jo upar CSS section mein discuss kiya, JS animation pe bhi equally apply hota hai kyunki dono ka rendering pipeline same hai.

Key Takeaways

  • Bezier curve control points se banti hai; CSS cubic-bezier(x1,y1,x2,y2) mein sirf P2, P3 tum control karte ho — P1=(0,0), P4=(1,1) fixed hain.
  • Built-in keywords (ease, ease-in, ease-out, ease-in-out, linear) sab pre-defined cubic-bezier values hain.
  • transition = ek-baar ka state-change animation (trigger-based); @keyframes + animation = multi-step, repeating, self-starting animation.
  • transitionend/animationend events har animated property/animation ke complete hone pe fire hote hain — propertyName/animationName aur elapsedTime milte hain.
  • Root cause: transform/opacity compositor thread pe GPU-accelerated chalte hain (Layout+Paint skip); width/left/margin jaisi geometry properties har frame Layout trigger karti hain — reflow ka perf cost.
  • setInterval kabhi mat use karo animation ke liye — timing imprecise hai, multiple timers batch nahi hote, aur background tab mein bhi chalta rehta hai. requestAnimationFrame in teeno ko fix karta hai.
  • Generic animate({duration, timing, draw}) helper — timing function progress-curve deta hai (bezier ka JS equivalent), draw DOM update karta hai, sab kuch rAF loop ke andar.

🎯 Interview Questions

  • cubic-bezier(x1,y1,x2,y2) mein 4 control points kyun nahi likhte, sirf 4 numbers?
    Hint: P1=(0,0) aur P4=(1,1) spec-fixed hain (animation hamesha 0% se 100% tak jaati hai) — sirf P2=(x1,y1) aur P3=(x2,y2) hi variable hain.
  • transform/opacity animate karna width/left animate karne se fast kyun hai — root mechanism batao.
    Hint: transform/opacity compositor thread pe GPU layers ke through handle hote hain (Layout+Paint skip); width/left geometry change karte hain, jisse browser har frame pe Layout (reflow) + Paint + Composite teeno dobara chalata hai.
  • setInterval se animation karne mein kya-kya galat ho sakta hai?
    Hint: display refresh rate se sync nahi hota (dropped/misaligned frames), multiple timers batch nahi hote (extra layout/paint), background tab mein throttle hoke bhi chalta rehta hai (CPU/battery waste).
  • requestAnimationFrame tab-hidden hone par kya karta hai, aur ye kyun important hai?
    Hint: browser automatically rAF callbacks ko pause kar deta hai jab tab visible nahi hota — CPU/battery save hota hai, setInterval ke against ek core advantage.
  • animate() helper mein timeFraction ko clamp (Math.min(1, ...)) karna kyun zaroori hai?
    Hint: rAF callback ka exact timestamp duration ko thoda overshoot kar sakta hai (frame boundaries align nahi hoti); bina clamp ke timing/draw function 1 se bade progress values dekh sakte hain jo unexpected visual glitch de sakta hai.
  • transition aur @keyframes animation mein kab kya use karoge?
    Hint: transition = simple state-A-to-state-B, trigger-based (hover, class toggle); @keyframes = multi-step/repeating/self-starting animations jo bina external trigger ke bhi chal sakti hain.
  • makeEaseOut wrapper function kaise kaam karta hai, "mirror trick" samjhao.
    Hint: 1 - timing(1 - timeFraction) — time-axis ko reverse karke original (ease-in-style) function ko call karta hai, phir result ko bhi reverse karta hai; ye geometrically curve ko horizontally+vertically flip kar deta hai, jisse slow-start curve slow-end ban jaati hai.
