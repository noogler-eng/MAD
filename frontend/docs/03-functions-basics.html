Functions Basics

Function declarations aur hoisting

Sabse common tareeka function banane ka — Function Declaration. Syntax simple hai: function keyword, naam, parentheses mein parameters, aur curly braces mein body. Yehi function baad mein naam se call hota hai.

function-declaration.js
// call hone se PEHLE bhi ye kaam karega — kyunki hoisting
showMessage(); // "Hello, main JavaScript hoon!" alert hoga

// function declaration — standalone statement, "function" keyword se shuru
function showMessage() {
  // ye variable sirf isi function ke andar exist karta hai — "local variable"
  let message = "Hello, main JavaScript hoon!";
  alert(message); // message ko popup mein dikhao
}

// function ke bahar 'message' access karne ki koshish — ReferenceError dega
// alert(message); // Error! message yahan defined nahi hai
🧠 Root-level: hoisting andar se kaise kaam karti hai

Engine jab kisi scope (script ya function body) mein enter karta hai, execution shuru karne se pehle ek creation phase chalta hai — us phase mein saare function declarations (poora function object, sirf naam nahi!) memory mein already allocate ho jaate hain, execution-order se pehle. Isiliye showMessage() ko call top pe likhne ke bawajood chalta hai — jab tak wo call ki line execute hoti hai, function already fully ready hota hai memory mein. Ye sirf var-jaisa "naam hoist, value nahi" wala behavior nahi hai — poora function definition hoist hoti hai. Function Expressions (let f = function(){}) is treatment se exempt hain — unka sirf variable naam (agar let/const) "temporal dead zone" mein reserve hota hai, value nahi — isi wajah se expression ko call-before-define karne pe error aata hai.

Local vs outer variables

Function ke andar declare kiya variable sirf us function ke andar visible hota hai — local variable. Lekin function apne bahar declare kiye variables ko read aur modify dono kar sakta hai — unhe "outer" ya (agar sabse bahar hai to) "global" variables kehte hain.

outer-variables.js
let userName = 'John'; // outer (global) variable

function showMessage() {
  userName = "Bob"; // koi local 'userName' nahi hai, isliye ye outer wala hi modify hoga
  let message = "Hello, " + userName; // naya local variable
  alert(message); // "Hello, Bob"
}

alert(userName); // "John" nahi — function call ke baad "Bob" hi rahega (permanently modified)
showMessage(); // call karte hi userName "Bob" ho jaata hai
alert(userName); // ab "Bob" — outer variable permanently badal gaya

function showMessageShadowed() {
  let userName = "Bob"; // agar yahan LOCAL userName declare karo, to ye "shadow" ho jaata hai
  let message = "Hello, " + userName; // local wala use hoga, outer wala touch hi nahi hota
  alert(message);
}

Shadowing ka matlab: agar function ke andar outer variable jaisa hi naam declare ho jaaye, to us function ke andar sirf local wala "dikhta" hai — outer wala completely hidden ho jaata hai (chhup jaata hai, isliye "shadow"). Best practice: globals kam se kam use karo — functions ko independent, self-contained rakho taaki unka behavior sirf unke parameters pe depend kare, kisi bahar ke hidden state pe nahi.

Parameters aur default values

Function declaration mein jo variables parentheses mein likhte ho unhe parameters kehte hain; call karte waqt unme jo values pass karte ho unhe arguments kehte hain. Important: JS values ko copy karke pass karta hai (primitives ke liye) — function ke andar parameter modify karne se caller ka original variable affect nahi hota.

default-parameters.js
// 'text' parameter ke liye default value diya — agar caller na de to ye use hoga
function showMessage(from, text = "no text given") {
  alert(from + ": " + text); // dono values ko concat karke dikhao
}

showMessage("Ann"); // "Ann: no text given" — text argument diya hi nahi, default chala
showMessage("Ann", undefined); // explicitly undefined pass karne pe bhi default chalega
showMessage("Ann", "Hi!"); // "Ann: Hi!" — dono arguments diye, default trigger hi nahi hoga

// default expression sirf tab evaluate hota hai jab argument miss/undefined ho —
// aur har call pe FRESH evaluate hota hai, ek baar cache nahi hota
function logCallTime(label, t = Date.now()) {
  // Date.now() har baar naya call hoga jab t argument nahi diya jaaye
  console.log(label, t);
}

// modern alternative: nullish coalescing (??) — sirf null/undefined pe fallback deta hai,
// 0 ya "" jaisi "falsy but valid" values ko preserve karta hai
function showCount(count) {
  count = count ?? 0; // agar count null/undefined hai tabhi 0 rakho
  alert(count);
}
⚠️ Default value ka || se manually likhna galat kyun

Purane code mein count = count || 0 pattern dikhta hai — lekin || har falsy value (0, "", NaN, false) pe fallback trigger karta hai, sirf missing/undefined pe nahi. Isse agar caller genuinely 0 pass kare, wo silently 0 hi rahega chahiye lekin || ise bhi overwrite kar dega — subtle bug. ?? ya function-parameter default (= 0) safe hai kyunki wo sirf undefined (ya missing argument) pe fire hota hai.

Return statement

return function ko turant terminate karke value caller ko wapas deta hai. Ek function ke andar return multiple jagah, multiple conditions ke saath ho sakta hai. Agar return hai hi nahi, ya value ke bina hai, function undefined return karta hai.

return-statement.js
function checkAge(age) {
  if (age >= 18) {
    return true; // yahin function turant exit ho jaata hai, neeche wala code nahi chalega
  } else {
    return confirm('Parents se permission li?'); // confirm() ka boolean result hi return ho jaata hai
  }
}

function doNothing() { // return hi nahi hai body mein
  // koi return statement nahi
}
alert(doNothing() === undefined); // true — implicit undefined return hota hai

// KHATARNAAK: return aur value ke beech newline mat daalo — ASI (Automatic Semicolon
// Insertion) 'return' ke baad turant semicolon insert kar deta hai
function buggyReturn() {
  return
    (
      "kuch value"
    );
}
alert(buggyReturn()); // undefined! JS ne 'return;' padha, value wali line unreachable ban gayi

Function expressions vs declarations

Function banane ka doosra tareeka — Function Expression: function ko ek assignment ke right side pe likhna, jaise koi normal value.

function-expression.js
// function expression: 'function' keyword yahan ek EXPRESSION ke andar hai (assignment ka right side)
let sayHi = function() {
  alert("Hello"); // body — declaration jaisa hi hai
}; // NOTE: semicolon lagta hai kyunki ye ek assignment statement hai

sayHi(); // "Hello" — sirf iske baad hi call kar sakte ho, pehle nahi

Comparison — dono syntax alag hain, isliye behavior bhi alag:

AspectFunction DeclarationFunction Expression
SyntaxStandalone function name(){} statementAssignment ke right side pe, let f = function(){}
HoistingPoora function definition creation-phase mein hoist hota haiSirf variable naam hoist (agar let/const, TDZ mein), value nahi
Call-before-defineKaam karta haiError deta hai (variable abhi assigned nahi)
Block scopeSirf apne containing block mein visible (strict mode)Normal variable scoping rules follow karta hai
block-scope-declaration.js
let age = 16; // test value

if (age < 18) {
  // function declaration ek block ({...}) ke andar hai — strict mode mein
  // ye sirf isi block ke andar visible hoga
  function welcome() {
    alert("Hello!");
  }
}

// welcome(); // Error: welcome is not defined — block ke bahar invisible hai

// Fix: function EXPRESSION use karo, variable ko block ke BAHAR declare karo
let welcomeFixed; // outer scope mein variable pehle se declare

if (age < 18) {
  welcomeFixed = function() { alert("Hello!"); }; // outer variable ko assign kiya, naya scope nahi banaya
} else {
  welcomeFixed = function() { alert("Greetings!"); };
}

welcomeFixed(); // ab kaam karta hai — outer variable ke through call

Recommendation: default Function Declarations use karo — readable, self-documenting, aur hoisting ki wajah se flexible order mein likh sakte ho. Function Expressions tab use karo jab conditional assignment chahiye, ya jab function inline ek anonymous callback ki tarah pass karna ho.

Function as a value — root internals

Ye is chapter ka sabse important mental-model shift hai: JavaScript mein function koi "magical language construct" nahi hai — ye ek special kind of value hai, aur andar se ek object hai (callable object). Isiliye function ko variables mein copy kar sakte ho, arguments ki tarah pass kar sakte ho, aur return kar sakte ho.

function-as-value.js
function sayHi() {
  alert("Hello");
}

alert(sayHi); // parentheses NAHI — function ka source code (as string) dikhega, call nahi hoga

let func = sayHi; // function object ko naye variable mein COPY kiya — ek naya function nahi bana

func(); // "Hello" — copy ke through original hi call ho raha hai
sayHi(); // "Hello" — original naam se bhi kaam karta hai

// proof ki function object hai: uspe custom property attach ho sakti hai
sayHi.counter = 0; // function object pe ek naya property daala — jaise kisi bhi object pe
sayHi.counter++; // property ko increment kiya
alert(sayHi.counter); // 1 — function pe stored state, closures se bhi related concept hai (ch.9)
🧠 Root-level: "function is an object" ka matlab engine ke andar

V8 (ya koi bhi JS engine) ke internal representation mein function object ek normal object ki tarah hi hota hai — uske paas properties store karne ke liye slots hote hain (jaise name, length, custom properties) — plus ek special hidden [[Call]] internal method jo use "callable" banata hai (yaani parentheses () laga ke invoke kiya jaa sakta hai). Yehi wo cheez hai jo function ko object se differentiate karti hai — typeof sayHi "function" return karta hai as a convenience, lekin sayHi instanceof Object bhi true hai. Isi "functions are first-class objects" property ki wajah se JS mein higher-order functions, callbacks, closures — sab possible hain. Ye chapter 9 (Advanced Functions) mein closures ke through aur deep jaayega.

Callback functions

Function ko value ki tarah treat karne ka sabse practical use case: ek function ko doosre function ke argument ki tarah pass karo, taaki wo "later" — kisi specific condition/event pe — call back kiya jaa sake.

callback-functions.js
// 'ask' function 3 parameters leta hai: sawaal, aur 2 CALLBACK functions
function ask(question, yes, no) {
  if (confirm(question)) { // user ne "OK" dabaya to true
    yes(); // jo callback 'yes' role mein pass hua, wahi call hoga
  } else {
    no(); // user ne "Cancel" dabaya to 'no' callback call hoga
  }
}

// callback functions inline, anonymous function EXPRESSIONS ki tarah pass kiye
ask(
  "Do you agree?",
  function() { alert("You agreed."); }, // yes callback — koi naam nahi diya, isliye "anonymous function"
  function() { alert("You canceled."); } // no callback — same tareeka
);

Ye exact pattern hi aage setTimeout, array methods (arr.map(fn), arr.filter(fn)), event listeners (el.addEventListener('click', fn)), aur Promises mein bhi repeat hota hai — sab jagah "function ko value ki tarah pass karo" wala concept hi core mein hai.

Arrow function basics

Arrow functions function expressions ka ek concise (chhota) alternative syntax hain — khaaskar simple, one-line callbacks ke liye useful.

arrow-basics.js
// basic form: (params) => expression — expression ka result AUTOMATICALLY return hota hai
let sum = (a, b) => a + b; // do parameters, implicit return
alert(sum(1, 2)); // 3

// single argument: round brackets OPTIONAL hain
let double = n => n * 2; // 'n' ke around () nahi lagaye — chalega
alert(double(3)); // 6

// no arguments: empty () REQUIRED hain, skip nahi kar sakte
let sayHi = () => alert("Hello!");
sayHi(); // "Hello!"

// multiline: curly braces {} lagani padti hain — aur ab return EXPLICIT likhna zaroori hai
let sumVerbose = (a, b) => {
  let result = a + b; // intermediate step likhna hai isliye {} zaroori hai
  return result; // {} ke andar automatic return NAHI hota — explicitly likhna padta hai
};

// callback ke roop mein arrow — 03 chapter tak ke liye yehi "basics" hai
ask(
  "Do you agree?",
  () => alert("You agreed."), // function expression ki jagah concise arrow
  () => alert("You canceled.")
);
📌 Ye "basics" hai — real differences chapter 9 mein

Is chapter mein arrow functions ko sirf ek syntactic shortcut ki tarah dekha — function expression jaisa hi behavior, bas chhota syntax. Lekin arrow functions ka ek fundamentally alag behavior hai jo yahan cover nahi kiya: unke paas apna this nahi hota (lexical this — surrounding scope se "borrow" karte hain), aur arguments object bhi nahi hota. Ye differences important hote hain jab arrow functions ko object methods ya constructors ki tarah use karne ki galti ki jaaye — poora detail Chapter 9 (Advanced Functions) mein milega.

Recap: JavaScript specials

Chapter 1-3 tak jo cover hua uska ek quick official recap — javascript.info ke "JavaScript Specials" article se, taaki context fresh rahe:

  • Code structure — statements semicolon se separate hote hain, lekin automatic semicolon insertion line breaks ko mostly delimiter treat kar leta hai. Code blocks {...} aur control-structures ke baad semicolon nahi chahiye.
  • Strict mode — "use strict" script ya function body ke top pe honi chahiye. Classes aur modules implicitly strict mode enable karte hain.
  • Variables — let, const (immutable binding), var (legacy, function-scoped). 8 data types: number, bigint, string, boolean, null, undefined, object, symbol. typeof null "object" deta hai — ye ek language quirk/historical bug hai.
  • Interaction — alert, prompt, confirm teeno modal (execution ko pause karte hain).
  • Operators — arithmetic, assignment, bitwise, ternary, logical (&& || !), aur nullish coalescing ??. Loose == type convert karta hai, strict === nahi.
  • Loops — while, do...while, for; break/continue, aur labels nested loops break karne ke liye.
  • Functions — teen tareeke: declarations, expressions, arrow functions. Default parameters support hote hain, aur function hamesha kuch return karta hai (undefined agar explicit return nahi hai).
💡 Interview mein jaldi bolne wali line

"Function declaration hoisted hoti hai poori definition ke saath, function expression sirf variable-naam hoist hota hai (value nahi) — isliye expression ko upar call karoge to error aayega." — ye ek line kaafi baar directly interview mein pucha jaata hai.

Key Takeaways

  • Function Declaration poori definition ke saath hoist hoti hai — call-before-define kaam karta hai. Function Expression sirf variable-naam hoist hota hai (agar let/ const, TDZ mein), value nahi — isliye call-before-define error deta hai.
  • Default parameter values har call pe fresh evaluate hote hain — cache nahi hote. ?? use karo || ke bajaye jab 0/"" jaisi falsy-but-valid values preserve karni ho.
  • return aur uski value ke beech kabhi newline mat daalo — ASI silently undefined return kar dega.
  • Function Declarations block-scoped hain (strict mode) — block ke bahar invisible. Conditional function assignment ke liye Function Expression + outer let use karo.
  • Function root mein ek object hai — copy ho sakta hai, properties attach ho sakti hain, argument ki tarah pass ho sakta hai (callback pattern).
  • Arrow functions is stage pe sirf concise syntax hain — this aur arguments ka lexical/absent behavior Chapter 9 mein aayega.

🎯 Interview Questions

  • Q1. Function declaration aur function expression mein hoisting ka fark kya hai? Hint: "poori definition hoist" vs "sirf naam hoist, TDZ".
  • Q2. count = count || 0 mein kya bug ho sakta hai jab count genuinely 0 ho? Hint: || falsy check karta hai, ?? sirf nullish check karta hai.
  • Q3. Default parameter expression kab evaluate hota hai — function define hote waqt ek baar, ya har call pe? Hint: Date.now() jaisa default example socho.
  • Q4. Ek if block ke andar declare kiya function declaration block ke bahar call kyun fail hota hai? Hint: block scope, strict mode behavior.
  • Q5. "Function is a value/object" — is statement ko justify karne ke liye do concrete examples do. Hint: copy to variable, custom property attach.
  • Q6. Callback function kya hota hai, aur kaunsi built-in JS APIs isi pattern pe based hain? Hint: setTimeout, addEventListener, array methods.
  • Q7. Arrow function ka multiline body likhte waqt return kyun explicit likhna padta hai? Hint: curly braces = normal function body, no implicit return.
  • Q8. return \n (value) likhne pe kya output aata hai aur kyun? Hint: Automatic Semicolon Insertion.
