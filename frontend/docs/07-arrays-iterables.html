Arrays & Iterables

Array JS mein "special" nahi hai — ye ek regular object hi hai jispe engine kuch extra internal tricks apply karta hai taaki ordered, index-based data fast handle ho sake. Is chapter mein hum dekhenge array andar se kaise kaam karta hai, kaunsa method mutate karta hai kaunsa nahi, aur for...of ke peeche ka Symbol.iterator protocol jisse tum khud ke custom iterable objects bana sakte ho.

Arrays objects hi hain — special handling ke saath

Root-level truth ye hai: typeof [] "object" return karta hai. Array ek regular object hi hai jiski property keys numeric strings hoti hain ("0", "1", "2"...), aur uske upar ek special auto-updating length property hoti hai. Bracket notation arr[0] wahi object property access syntax hai jo obj["0"] karta — bas array ke case mein engine internally is pattern ko recognize karke ek optimized, contiguous memory layout use karta hai (jaisa C arrays mein hota hai), jab tak tum us pattern ko todo nahi.

length property — auto-tracking greatest index
let arr = [1, 2, 3, 4, 5];                 // array literal — 5 elements, indexes 0 se 4

console.log(arr.length);                          // 5 — highest index (4) + 1, engine ye khud maintain karta hai

arr[100] = "boom";                          // index 100 pe direct assign — koi error nahi, arrays sparse ho sakte hain

console.log(arr.length);                          // 101 — length khud-ba-khud "highest index + 1" pe update ho gaya

arr.length = 2;                                 // length ko WRITE karna bhi allowed hai — special behavior

console.log(arr);                               // [1, 2] — array TRUNCATE ho gaya, baaki elements permanently delete

arr.length = 5;                                 // length badha diya, lekin naye slots "empty" hain (holes), values nahi

console.log(arr[3]);                            // undefined — slot exist karta hai but koi value assign nahi hui

length koi "computed getter" nahi hai jo har baar array scan karke count nikaale — engine ise ek internal field ki tarah maintain karta hai, har mutating operation (push, pop, direct index assignment) ke saath sync mein update karta hai. Isiliye arr.length read karna O(1) hai, O(n) scan nahi.

⚠️ Array ko "generic object" ki tarah treat mat karo

V8 (Chrome/Node ka engine) arrays ke liye do internal representations rakhta hai — packed (dense, sab elements same type, koi gap nahi — fast, contiguous memory) aur dictionary mode (jab tum non-numeric properties add karte ho, gaps (sparse arrays) banate ho, ya reverse order mein fill karte ho). Ek baar dictionary mode mein gaya array wapas packed nahi hota, aur uske baad ke saare operations slower ho jaate hain — engine ab optimized fast-path use nahi kar sakta.

push/pop/shift/unshift — internals aur performance

Ye 4 methods array ke dono ends (start/end) pe elements add/remove karte hain — lekin inki performance bilkul alag hai, aur ye difference internal memory model se directly nikalta hai.

push/pop — end pe operate karte hain (fast)
let fruits = ["Apple", "Orange"];            // array with 2 elements, indexes 0 aur 1

fruits.push("Pear");                          // index 2 pe naya element daalo — kisi aur element ka index nahi badalta

console.log(fruits);                            // ["Apple", "Orange", "Pear"]

let last = fruits.pop();                    // last index (2) ka element hata ke return karo

console.log(last);                              // "Pear" — jo element pop hua wahi return hota hai

console.log(fruits);                            // ["Apple", "Orange"] — baaki dono elements ka index waisa hi raha (0, 1)
shift/unshift — start pe operate karte hain (slow)
let fruits = ["Apple", "Orange", "Pear"];  // 3 elements, indexes 0,1,2

let first = fruits.shift();                // index 0 ka element nikaalo aur return karo

console.log(first);                             // "Apple"

// yahaan internally: "Orange" jo index 1 pe tha, wo index 0 pe SHIFT hua,
// "Pear" jo index 2 pe tha, wo index 1 pe SHIFT hua — HAR remaining element move hua

console.log(fruits);                            // ["Orange", "Pear"] — indexes re-numbered 0,1

fruits.unshift("Apple");                    // index 0 pe naya element daalo

// internally: "Orange" (index 0) ko index 1 pe MOVE karo, "Pear" (index 1) ko index 2 pe MOVE karo,
// TAB jaake "Apple" ko index 0 pe likho — insert se pehle HAR element ko ek slot right shift karna padta hai

console.log(fruits);                            // ["Apple", "Orange", "Pear"]

Root cause: array ka index ordering hi uski identity hai — arr[0] hamesha "first" element hona chahiye. Jab pop last element hataata hai, kisi doosre element ka index badalta hi nahi — sirf length ek se kam ho jaata hai aur last slot free ho jaata hai. Isliye push/pop O(1) (amortized constant time) hote hain.

Lekin shift/unshift ke case mein, agar index 0 pe kuch add/remove karna hai, to baaki saare N elements ka index shift karna padega taaki ordering sahi rahe. Ye O(n) operation hai — jitne zyada elements array mein, utna zyada time. Ek 1-million-element array pe baar-baar unshift karna production mein real performance bottleneck ban sakta hai.

🧠 Senior Dev Note: queue implement karna ho to

Agar tumhe FIFO queue chahiye jisme frequently front se remove ho, to plain array pe shift() loop mein mat lagao — O(n²) ban jaayega. Ya to array ko reverse order mein maintain karo aur pop/push use karo (dono O(1)), ya phir ek index pointer maintain karke "logical shift" simulate karo (elements delete na karke bas pointer aage badhao), ya real linked-list-based structure use karo. React/Redux jaise large state trees mein bhi yahi wajah hai ki array ke start mein insert/delete se bachte hain — end pe operate karna hamesha cheaper hota hai.

Array loop karne ke tareeke

for vs for...of vs for...in
let arr = ["a", "b", "c"];

for (let i = 0; i < arr.length; i++) {  // classic index-based for loop — fastest, engine sabse zyada optimize karta hai
  console.log(arr[i]);                             // i se manually index access karo
}

for (let item of arr) {                        // for...of — Symbol.iterator protocol use karta hai (neeche detail mein)
  console.log(item);                            // direct VALUE milta hai, index nahi — cleanest syntax
}

for (let key in arr) {                         // for...in — ARRAYS ke liye AVOID karo
  console.log(arr[key]);                          // key yahaan STRING hai ("0","1","2"), number nahi
}

for...in object ki saari enumerable properties ko iterate karta hai — sirf numeric indexes nahi. Agar kisi ne array pe ek extra custom property add ki hai (jaise arr.someLabel = "x"), to for...in use bhi loop mein include kar lega, jabki for...of aur index-based loop sirf actual array elements dekhte hain. Ye general-purpose object-iteration ke liye design hua tha, arrays ke liye nahi — isliye engines isse array-specific fast-path optimize nahi kar paate, aur real-world benchmarks mein ye 10-100x slower dikhta hai bade arrays pe.

splice, slice, concat

splice — mutates original, remove+insert dono
let arr = ["I", "study", "JavaScript"];

arr.splice(1, 1);                          // index 1 se shuru karke 1 element REMOVE karo — original ARRAY mutate hoga

console.log(arr);                               // ["I", "JavaScript"] — "study" gaya

let removed = arr.splice(0, 1, "Let's", "dance"); // index 0 se 1 hataao, wahan 2 naye insert karo

console.log(arr);                               // ["Let's", "dance", "JavaScript"]

console.log(removed);                           // ["I"] — splice hataye gaye elements ka NAYA array return karta hai
slice — original ko touch nahi karta, copy return karta hai
let arr = ["t", "e", "s", "t"];

console.log(arr.slice(1, 3));                    // index 1 se 3 TAK (3 EXCLUDE) — ["e","s"], NAYA array

console.log(arr.slice(-2));                       // negative index — end se count, ["s","t"]

console.log(arr);                               // ["t","e","s","t"] — original BILKUL untouched

let copy = arr.slice();                       // bina arguments — pura shallow-copy banane ka common idiom
concat — arrays/values merge karke naya array
let arr = [1, 2];

console.log(arr.concat([3, 4]));                // [1,2,3,4] — arrays ke andar ke elements FLATTEN hoke merge hote hain

console.log(arr.concat([3, 4], 5, 6));           // [1,2,3,4,5,6] — plain values direct push ho jaate hain

console.log(arr);                               // [1,2] — arr khud MUTATE NAHI hua, naya array return hua

forEach, indexOf/includes, find/filter

forEach + searching methods
["Bilbo", "Gandalf", "Nazgul"].forEach((item, index) => { // callback ko (element, index) milta hai
  console.log(`${index}: ${item}`);            // forEach ka return value HAMESHA undefined hai — koi array nahi banta
});

let arr = [1, 0, false];

console.log(arr.indexOf(0));                       // 1 — strict === comparison se dhundta hai

console.log(arr.includes(1));                      // true — indexOf se NAYA (SameValueZero algorithm), NaN bhi handle karta hai

let users = [{id:1,name:"John"}, {id:2,name:"Pete"}];

let user = users.find(item => item.id == 1);    // pehla MATCHING element return karta hai, mila to loop TURANT ruk jaata hai

console.log(user.name);                         // "John"

let someUsers = users.filter(item => item.id < 3); // find se DIFFERENT — filter SAARE matching elements ka array deta hai

console.log(someUsers.length);                 // 2 — poora scan hota hai, early-exit nahi

map aur sort — comparator ka gotcha

map — transform karke naya array
let lengths = ["Bilbo", "Gandalf", "Nazgul"].map(item => item.length); // har element ko length se REPLACE karo

console.log(lengths);                          // [5, 7, 6] — original array ka SAME length, ek naya array

sort() ka default behavior ek classic gotcha hai jo har senior interview mein puchha jaata hai: bina comparator ke, sort() SAARE elements ko string mein convert karke compare karta hai — chahe wo numbers hi kyun na hon.

sort() — default string coercion trap
let arr = [ 1, 2, 15 ];

arr.sort();                                    // NO comparator diya — default STRING sort chalega

console.log(arr);                               // [1, 15, 2] — GALAT! kyunki "15" < "2" as STRINGS (char '1' < char '2')

arr.sort((a, b) => a - b);                // comparator: negative = a pehle, positive = b pehle, 0 = same

console.log(arr);                               // [1, 2, 15] — SAHI numeric sort ab hua

let countries = ["Österreich", "Andorra", "Vietnam"];

countries.sort((a, b) => a.localeCompare(b));   // special/accented characters ke liye locale-aware compare

console.log(countries);                         // correct alphabetic order
⚠️ sort() array ko IN-PLACE mutate karta hai

arr.sort() naya array return nahi karta — wahi arr reorder karke usi reference ko return karta hai. Agar tumhe original order preserve karni hai (e.g. React state ya Redux mein), pehle [...arr].sort(...) ya arr.slice().sort(...) se copy banao, phir sort karo — warna original data structure silently mutate ho jaayega aur reference-equality checks (jo React re-render decide karte hain) confuse ho sakte hain.

reduce — step-by-step mechanics

reduce() array ko ek single value mein "collapse" karta hai, ek accumulator ko carry karte hue. Andar kya ho raha hai wo dekhna zaroori hai kyunki interview mein iski exact mechanics puchhi jaati hai:

reduce — accumulator step by step
let arr = [1, 2, 3, 4, 5];

let result = arr.reduce((sum, current) => sum + current, 0); // callback(accumulator, item), 0 = initial value

// Run 1: sum(accumulator) = 0 (initial), current = arr[0] = 1  →  return 0+1 = 1
// Run 2: sum = 1 (pichhle run ka result), current = arr[1] = 2 →  return 1+2 = 3
// Run 3: sum = 3, current = arr[2] = 3                        →  return 3+3 = 6
// Run 4: sum = 6, current = arr[3] = 4                        →  return 6+4 = 10
// Run 5: sum = 10, current = arr[4] = 5                       →  return 10+5 = 15
// reduce ab aur elements nahi bache, to FINAL accumulator return karta hai

console.log(result);                            // 15

let noInitial = arr.reduce((sum, current) => sum + current);  // initial value NAHI diya

// jab initial value MISSING ho: reduce pehla element (arr[0]) ko hi STARTING accumulator maan leta hai,
// aur loop index 1 se shuru karta hai — behavior SAME hai, bas Run 1 skip ho jaata hai

console.log(noInitial);                        // 15 — same result, but EMPTY array pe ye TypeError throw karega
⚠️ reduce() bina initial value ke — empty array pe crash

Agar array empty hai aur initial value nahi di, reduce "Reduce of empty array with no initial value" TypeError throw karta hai — kyunki accumulator start karne ke liye koi element hi nahi mila. Production code mein hamesha initial value do (jaise reduce(fn, 0) ya reduce(fn, [])), taaki edge case safe rahe.

Iterable protocol — Symbol.iterator

for...of loop kisi jaadu se kaam nahi karta — wo har object pe ek well-defined protocol follow karta hai. Jab tum for (let x of obj) likhte ho, engine internally ye steps karta hai:

  1. Object ki obj[Symbol.iterator] method ko ek baar call karta hai — ye ek "iterator object" return karti hai.
  2. Us iterator object ke .next() method ko baar-baar call karta hai.
  3. Har .next() call se { value, done } shape ka object milta hai.
  4. Jab done: true milta hai, loop turant ruk jaata hai — value is baar ignore hota hai.

Arrays, strings, Map, Set — sab built-in Symbol.iterator implement karte hain, isiliye ye sab for...of mein directly chal jaate hain. Plain {} object iterable nahi hai — usme ye method missing hoti hai.

Custom iterable object banana

Ye protocol khud implement karke hum apna ek object bana sakte hain jo for...of mein directly use ho sake — bina usko pehle array mein convert kiye:

Custom "range" iterable — separate iterator object
let range = {
  from: 1,                                // range ki starting value — plain data property
  to: 5                                   // range ki ending value (inclusive)
};

range[Symbol.iterator] = function() {              // well-known symbol key pe method assign — for...of isi ko dhundta hai
  return {                                // ek NAYA, alag "iterator" object return kar rahe hain (range se independent state)
    current: this.from,              // iterator apna khud ka "current position" track karta hai
    last: this.to,                   // upper bound copy kar li closure mein

    next() {                            // for...of is method ko repeatedly call karega
      if (this.current <= this.last) {  // abhi range khatam nahi hui
        return { done: false, value: this.current++ }; // current return karo, PHIR increment karo (post-increment)
      } else {
        return { done: true };       // range khatam — for...of ko signal ki loop ruk jaaye
      }
    }
  };
};

for (let num of range) {                     // engine: range[Symbol.iterator]() call karo, phir .next() loop mein
  console.log(num);                            // 1, 2, 3, 4, 5 — ek ek karke print
}

// FAYDA: alag iterator object banane se range object khud STATELESS reh gaya —
// isliye do parallel for...of loops SAME range pe INDEPENDENTLY chal sakte hain

Ek shortcut approach bhi hai jahan object khud hi apna iterator ban jaata hai (next aur state dono usi object pe) — simpler lekin ek limitation ke saath:

Merged iterable — object khud apna iterator hai (limitation ke saath)
let range = {
  from: 1,
  to: 5,

  [Symbol.iterator]() {                    // computed method name syntax — Symbol.iterator ko method key banaya
    this.current = this.from;       // state ko object pe HI reset kar rahe hain (naya object nahi banaya)
    return this;                       // object khud ko iterator ki tarah return kar raha hai (usme next() hai)
  },

  next() {
    if (this.current <= this.to) {
      return { done: false, value: this.current++ };
    } else {
      return { done: true };
    }
  }
};

for (let num of range) {
  console.log(num);                            // 1, 2, 3, 4, 5
}

// LIMITATION: yahaan sirf EK "current" state hai (object pe), isliye
// DO nested for...of loops SAME range pe ek doosre ko interfere karenge
📌 Iterable vs array-like — do alag concepts

Iterable = Symbol.iterator implement karta hai (behavior-based, for...of mein chalta hai). Array-like = numeric indexes + length property rakhta hai (shape-based, sirf arr[i] se access karo). Ek object dono ho sakta hai, ek ho sakta hai, ya koi nahi — jaise {0: "a", 1: "b", length: 2} array-like hai but iterable nahi (bina Symbol.iterator ke, for...of throw karega). Array.from(arrayLikeOrIterable) dono cases handle karta hai aur ek asli array banata hai — jispe phir map, filter, etc use kar sako.

🧠 Senior Dev Note: for...of internally kya use karta hai

Modern JS mein bahut si cheezein Symbol.iterator ke upar hi built hain — spread operator ([...iterable]), destructuring (let [a, b] = iterable), Array.from, aur generators (jo automatically Symbol.iterator implement karte hain). Jab tum khud ek custom data structure banate ho (jaise ek linked list, ya paginated data-fetcher), Symbol.iterator implement karke usko is poore ecosystem ke saath free mein compatible bana sakte ho — bina har jagah manual .toArray() conversion likhe. Generators (function*) isko aur simple bana dete hain kyunki wo khud-ba-khud ek valid iterator return karte hain.

Key Takeaways

  • Array ek regular object hai jispe engine special optimizations (contiguous, packed memory) apply karta hai — length auto-tracking hai aur writable bhi.
  • push/pop end pe operate karke O(1) hain; shift/unshift start pe operate karte hain to har baaki element re-index karna padta hai — O(n).
  • for...in array pe avoid karo — ye all-properties enumerate karta hai aur slow hai; for...of ya index-based for use karo.
  • sort() bina comparator ke default STRING comparison karta hai — numbers ke liye hamesha (a, b) => a - b do.
  • Mutating methods (splice, sort, reverse, push/pop/shift/unshift) original ko badalte hain; non-mutating (slice, concat, map, filter) naya array return karte hain.
  • reduce ek accumulator ko step-by-step carry karta hai; initial value na do to first element accumulator ban jaata hai, aur empty array pe error throw karta hai.
  • for...of Symbol.iterator protocol follow karta hai — [Symbol.iterator]() se ek iterator object milta hai jiska .next() repeatedly call hota hai jab tak done: true na mile.
  • Iterable (behavior: Symbol.iterator) aur array-like (shape: indexes + length) alag concepts hain — Array.from() dono ko real array mein convert kar sakta hai.

🎯 Interview Questions

  • push/pop O(1) kyun hain lekin shift/unshift O(n)?
    Hint: array ordering maintain karne ke liye start pe insert/remove hone par baaki saare elements ka index shift karna padta hai; end pe operate karne se doosre elements ke index untouched rehte hain.
  • arr.length = 2 likhne se kya hota hai agar array mein 5 elements the?
    Hint: array truncate ho jaata hai, index 2 se aage ke elements permanently delete ho jaate hain — length writable property hai, sirf readonly counter nahi.
  • sort() bina argument ke [10, 2, 1] ko kaise sort karega, aur kyun?
    Hint: [1, 10, 2] — default sort saare elements ko STRING mein convert karke lexicographic (char-by-char) compare karta hai.
  • map() aur forEach() mein practical farak kya hai?
    Hint: map() naya array return karta hai (transform ke liye), forEach() hamesha undefined return karta hai (sirf side-effects ke liye) — forEach ka return chain nahi kar sakte.
  • reduce() mein initial value optional hai — na dene par kya risk hai?
    Hint: first element hi starting accumulator ban jaata hai aur loop index 1 se shuru hota hai; agar array EMPTY hai to TypeError throw hoga kyunki koi starting value hi nahi mila.
  • for...of kaise pata karta hai ki loop kab rukna hai?
    Hint: object ke Symbol.iterator method se mila iterator object ka .next() baar baar call hota hai; jis moment {done: true} return hota hai, loop stop ho jaata hai.
  • Ek object array-like hai lekin iterable nahi — for...of chalane pe kya hoga?
    Hint: TypeError throw hoga "is not iterable" — kyunki for...of ko Symbol.iterator method chahiye, sirf numeric-index+length shape kaafi nahi hai.
  • Kya splice() aur slice() same kaam karte hain? Farak batao.
    Hint: naam similar hone ke bawajood bilkul alag — splice() original array ko MUTATE karta hai (remove+insert), slice() original ko chhue bina ek NAYA sub-array copy return karta hai.
